# Repository memory

What AI Office's Agents have learned about this repository, one entry per line. Every Agent reads it at the start of a task. The Floor's Manager curates it through pull requests, merging duplicates and dropping stale entries: change it the same way.

- bananaburn.app/registro no tiene página (solo redirige a quien tiene sesión); el enlace de registro es /entrar?modo=registro (`SIGNUP` en src/app/(marketing)/content.tsx).
- La duración del primer entreno sale de `FIRST_MAX_MIN` (15) y `FIRST_HOME_MIN` (12, en casa sin equipo, solo si eligió gym o mixto) en src/lib/engine/index.ts; la copy dice 12 min, nunca 10 ni 15–20.
- Lo que se quita de marketing va a marketing/archivo/ con `git mv`, una línea «ARCHIVADO (#issue). No se publica.» con el motivo, y una fila en marketing/archivo/README.md.
- marketing/comunidad/generar.mjs regenerates every historias/*.json each run; the 1–8 nov bases come out byte-identical, so only the days you changed show up in git status.
- Several content PRs edit marketing/comunidad/ in parallel, so run `git merge-tree --write-tree HEAD main` before finishing and merge main if it reports conflicts.
- Content issues split from one report (like #213–#216 from #202) edit the same `marketing/comunidad/` files, so merge `main` before finishing and keep any marker text that another issue's test checks (for example "ARCHIVADO (#215)" in `contenido-noviembre-215.test.ts`).
- A new step in `runReminders` that reads profiles needs every fake Supabase client in the tests to support its query methods (e.g. `gte` in beta-fin-qa.test.ts), or a mock throws a TypeError and `stats.errors` changes.
- If vitest dies with "Channel closed", leftover `node (vitest N)` workers from an earlier run are using up the 4 GB cgroup: kill them by PID (pkill -f with "(" fails as a regex) and run `npx vitest run --maxWorkers=4`.
- To render the workout player (or anything that imports src/components/workout/ui.tsx) in vitest, mock `@/components/workout/workout.module.css`, `next/navigation` and `@/components/analytics`, because Vite fails on the Tailwind PostCSS config with "Invalid PostCSS Plugin".
- If a full `npx vitest run` dies with "Channel closed / ERR_IPC_CHANNEL_CLOSED", workers from an earlier run are still alive: kill them with `pgrep -f "node.*vitest" | xargs -r kill -9` and run again with `--maxWorkers=4`.
- Checkout purchases (ONVO webhook and Tilopay return) send Subscribe by CAPI with `purchaseEventId(subscription)` from src/lib/meta-pixel.ts, the same id as the `/pago/exito` pixel; automatic charges use `onvo.first:<sub>` or the charge's `event_key`.
- `npx next build` can get "Killed" if vitest is still running; run it alone with `NODE_OPTIONS=--max-old-space-size=3072`, and if the full vitest run fails with ERR_IPC_CHANNEL_CLOSED, rerun with `--maxWorkers=2`.
