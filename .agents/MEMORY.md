# Repository memory

What AI Office's Agents have learned about this repository, one entry per line. Every Agent reads it at the start of a task. The Floor's Manager curates it through pull requests, merging duplicates and dropping stale entries: change it the same way.

- The sandbox can start without node_modules; run `npm ci --no-audit --no-fund` (about 1–2 min) before tsc, eslint, vitest or next build, otherwise `npx tsc` installs the wrong "tsc" package.
- If the full `npx vitest run` dies with "Channel closed" (ERR_IPC_CHANNEL_CLOSED), the 4 GB cgroup ran out: kill leftover `node (vitest N)` workers by PID and rerun alone with `--maxWorkers=2`; rerun files that time out at 5 s under load alone before blaming your change.
- Never run `pkill -f vitest` or `pkill -f "next start"` in the same Bash command as other work: the pattern matches the shell's own command line and kills it (exit 144).
- `npx next build` can be OOM-killed (exit 137) at "Linting and checking validity of types": run it alone with `NODE_OPTIONS=--max-old-space-size=2560`, and if still killed, run tsc and eslint on their own, then `next build --no-lint`.
- Sandbox network is filtered: curl a local `next start` with `curl --noproxy '*' http://127.0.0.1:PORT/...` (via the proxy it's 403), and Playwright browsers can't be downloaded, so layout checks are vitest tests on markup and real viewport checks go to QA.
- docs from open PRs (e.g. docs/ux/auditoria-primer-entreno.md in #251) can be read with `gh api 'repos/<owner>/<repo>/contents/<path>?ref=refs/pull/<n>/head' -H 'Accept: application/vnd.github.raw'`, because git fetch and WebFetch to GitHub are blocked.
- No DOM test library exists: render client components with renderToStaticMarkup (mock next/navigation, server actions, @/lib/supabase/client; see src/app/(auth)/entrar/login-form.test.tsx), or for hooks mock `react` and call the component (see src/components/pagos/initiate-checkout.test.tsx).
- Pages with `use()`/Suspense (e.g. the home page in src/app/(marketing)/page.tsx) fail with renderToStaticMarkup in vitest; render them with `prerender` from "react-dom/static.edge" and read the prelude with `new Response(prelude).text()`.
- To render the workout player (or anything that imports src/components/workout/ui.tsx) in vitest, mock `@/components/workout/workout.module.css`, `next/navigation` and `@/components/analytics`, because Vite fails on the Tailwind PostCSS config with "Invalid PostCSS Plugin".
- When testing the whole Hoy page (src/app/(app)/app/page.tsx), import it once in a beforeAll with a long timeout, or a late snapshot is saved under the next test's name; cards rendered after useEffect are empty in prerender (see src/lib/hoy-ingles-activacion.test.tsx).
- To call a Next route handler in vitest (e.g. /api/pagos/tarjeta), mock `@/lib/supabase/server` with `getViewer`, mock `@/lib/security/db-rate-limit` partially (keep `keyPart`) and point `@/lib/supabase/admin` at `fakeDb`; `src/lib/simulacro-1-diciembre.test.ts` is the example.
- Cron tests' fake Supabase clients (notify-run-*.test.ts, beta-fin-qa.test.ts) support only select/in/eq/gte/gt/is/order/limit/range/upsert/insert (no `not`/`neq`); new reads must filter in JS or extend every mock, or a TypeError changes `stats.errors`.
- To test a SQL file that only reads funnel_events, load supabase/tests/stub.sql plus supabase/migrations/0061_eventos_embudo.sql in PGlite (see src/app/api/track/registro-embudo.test.ts); PGlite takes about 1 s to start whatever it loads, so slow tests need a longer timeout.
- PGlite scripts must live inside the repo (e.g. ./x.tmp.mjs) to resolve @electric-sql/pglite; trial_charges rows of kind 'prueba' need trial_ends_at = trial_started_at + 7 days (check trial_charges_seven_days).
- UI texts quoted in marketing/anuncios/campana-9-noviembre.md (guided.tsx, first-day Hoy buttons) are checked by src/lib/campana-9-noviembre.test.ts and src/lib/engine/first-session-casa.test.tsx, so change the copy, the doc and the tests together.

- Text for English accounts that comes from data rather than code (challenge tasks, recipe names, announcements) goes through `translateContent` in src/lib/i18n/content.ts, and tasks with numbers need a template in `CHALLENGE_PATTERNS` (src/lib/i18n/en/challenges.ts).

- /api/track drops any string prop that matches the PII regex (a digit followed by 6+ digits, spaces, dots or dashes, then a digit), so ISO dates like "2026-11-09" are silently removed from funnel_events props; send numbers or omit dates.
- src/app/api/track/event.ts is imported by the client component src/components/analytics.tsx (landing bundle), so anything it imports must have no engine or server dependencies; put shared constants in a small module (e.g. src/lib/regreso-kinds.ts).
